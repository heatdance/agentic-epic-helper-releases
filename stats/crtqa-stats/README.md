# CRTQA stats

Management-oriented rollups for **Test Case Development** time: a **manual baseline corpus** vs **AI-assisted comparison** tasks (agentic epic helper / this workspace).

Command: [`/crtqa-stats`](../../.cursor/commands/crtqa-stats.md) · Rollup tool: [`automation/docs/crtqa-stats.md`](../../automation/docs/crtqa-stats.md)

## Model

| Role | Use |
|------|-----|
| **corpus** | Historical manual baseline — medians define “expected hours” |
| **comparison** | AI-assisted work — compared to corpus for **% time saved** |

On the **first run**, each **Epic** is attested: if it was **already AI-assisted**, its tasks go to **comparison**, not corpus. Later **incremental** runs add new done tasks (default comparison, confirm per task).

**Representable** benchmark: **≥ 4** corpus tasks in a category (or category×size cell). Sparse cells show “benchmark pending” for that row only.

## Modes

| Mode | Purpose |
|------|---------|
| `initial_assessment` | Build corpus + comparison from full done cohort |
| `incremental_update` | Add new done keys; regenerate report if none |
| `full_refresh` | Re-fetch and reclassify existing keys |

Example: `/crtqa-stats mode=initial_assessment jira_user=<you>`

## Cohort (Jira)

- Epics: `project = CRT AND issuetype = Epic AND "test lead" = <user>`
- Tasks: `project = CRTQA AND issuetype = "Test Execution" AND summary ~ "Test Case Development" AND "Epic Link" = <CRT-KEY> AND statusCategory = Done`

## Files

| Path | Notes |
|------|--------|
| `latest.md` | Committed report (regenerated by rollup) |
| `temp/categories.json` | Coarse categories (FE/BE/API/…) + SP size bands |
| `state/last-sync.json` | Schema v3 cumulative state (gitignored) |
| `state/longitudinal.json` | Per-run history (gitignored) |
| `raw/run-*.jsonl` | Audit trail (gitignored) |

## Taxonomy

Five categories: `fe`, `be`, `api`, `cross_cutting`, `other`. Size bands: `< 1 SP`, `1–2 SP`, `3+ SP`, `sp_unknown`.

Interpretation is **associative, not causal**.
